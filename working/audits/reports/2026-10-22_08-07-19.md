## Findings

### AUDIT-001 - A running conversation silently blocks submission to another conversation

**Class:** `defect`

**Severity:** P2

**Confidence:** High

**Area:** Controller submission lifecycle and independent Agent conversations.

**Reachability:** Submit a normal text request in conversation A. While A is still responding, use Sessions to select an idle conversation B, enter text, and submit it. The condition lasts for A's full Agent turn and does not require precise event ordering.

**Blast radius:** Other idle conversations reached through the same Controller's text interface while its earlier prompt remains pending.

**Reversibility:** Wait for A to finish, or return to A and cancel it, then resubmit B's retained draft. No draft or persisted content loss was observed.

**Documented trade-off:** [Agent sessions:70](../../../docs/agent-sessions.md#L70) retains the session directory and concurrency behavior. The executable boundary rejects an already-running target session at [session-execution.ts:34](../../../apps/desktop/src/main/agent/sessions/session-execution.ts#L34), while [session-execution.ts:72](../../../apps/desktop/src/main/agent/sessions/session-execution.ts#L72) permits up to eight concurrent tasks. [The existing concurrency test](../../../apps/desktop/test/unit/main/agent/sessions/agent-sessions.test.ts#L330) confirms this capacity. Preventing duplicate submission to one target is reasonable; serializing all conversations behind one pending UI request is not that boundary.

**Decision status:** `drift`

**Why this finding is outside the accepted boundary:** UI pending state has no session identity, so a request owned by A suppresses an otherwise valid request to B before it reaches the host. The host's intended concurrency limit is never consulted.

**Evidence:**

- [Controller.tsx:42](../../../packages-renderer/controller/src/components/Controller.tsx#L42): one component-wide `sending` boolean.
- [Controller.tsx:87](../../../packages-renderer/controller/src/components/Controller.tsx#L87): `sending && session.status !== "running"` silently returns; the flag is cleared only after the awaited prompt completes.
- [agent-ipc.ts:128](../../../apps/desktop/src/main/ipc/agent-ipc.ts#L128) and [session-execution.ts:88](../../../apps/desktop/src/main/agent/sessions/session-execution.ts#L88): the returned prompt promise spans execution, rather than only admission.
- [SessionsPanel.tsx:30](../../../packages-renderer/controller/src/sessions/SessionsPanel.tsx#L30) and [selection:55](../../../packages-renderer/controller/src/sessions/SessionsPanel.tsx#L55): creating/selecting another conversation remains possible.
- [ChatComposer.tsx:51](../../../packages-renderer/controller/src/chat/ChatComposer.tsx#L51): Send is enabled when there is a draft and no model change, regardless of the hidden global guard.
- [controller-task-label.ts:18](../../../packages-renderer/controller/src/components/controller-task-label.ts#L18): the global flag overrides the selected conversation's task feedback.

**Observed behavior:** The real-component reproduction submitted A, selected idle B, entered another draft, and submitted again. Send was enabled, but the API call count stayed at one, B stayed idle, the draft remained, and the task label read `Sending request…`. Once A completed, submitting the unchanged draft produced the second API call, correctly addressed to B.

**Impact:** The ordinary multi-conversation workflow is unavailable during another conversation's work, with no error explaining the rejected submission. Long provider/tool activity extends the blockage across the whole turn.

**Missing or inadequate verification:** Host tests verify concurrent sessions but do not exercise Controller state ownership during selection changes. The synthetic component reproduction establishes the submission failure, not native Electron presentation or paid-provider access.

**Minimum sufficient remediation:** Track submission state by target conversation/request, and derive the selected conversation's guard, busy indicator, and feedback from that identity. Each completion must clear only its own pending request. Preserve supplements for a running conversation and retain the existing host concurrency boundary. No IPC or Agent execution contract change is required.

**Verification scope:** A component regression should keep A pending, switch to B, and verify that B immediately receives its own prompt. Completing A must not clear B's pending state. Returning to A must preserve supplement/cancellation behavior. Run affected Controller checks and a focused native conversation-switch scenario during remediation.
