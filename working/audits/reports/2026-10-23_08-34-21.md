## Findings

### AUDIT-001 - Interactive prompts instruct models to send a forbidden tool field

**Class:** `defect`

**Severity:** P2

**Confidence:** High

**Area:** Session/provider ownership of execution metadata and direct tool argument contracts.

**Reachability:** An interactive Agent follows the instruction added to every prompt and includes `executionId` in a supplied canvas tool call. This requires no malformed user request.

**Blast radius:** The current direct DeepSeek canvas-tool path, including block-launched interactive sessions.

**Reversibility:** No mutation is dispatched for the rejected call. A model may recover by omitting the field, but following the instruction consistently keeps failing and consumes tool rounds.

**Documented trade-off:** [Agent sessions:101](../../../docs/agent-sessions.md#L101) explicitly makes execution identity a trusted session-manager input, separate from model-generated arguments; the legacy gateway retains its own compatibility contract.

**Decision status:** `drift`

**Why this finding is outside the accepted boundary:** The common session layer introduces an MCP-specific argument requirement into a direct provider path that deliberately does not accept that argument.

**Evidence:**

- [session-execution.ts:85](../../../apps/desktop/src/main/agent/sessions/session-execution.ts#L85) prefixes interactive text with an instruction to include the exact `executionId` in every tool call.
- [desktop-application.ts:480](../../../apps/desktop/src/main/desktop-application.ts#L480) passes the unextended `canvasToolDefinitions` to the direct host and separately supplies trusted execution authorization.
- [canvas-tools.ts:17](../../../apps/desktop/src/main/canvas/canvas-tools.ts#L17) defines strict tool schemas without that field; [deepseek-agent-host.ts:296](../../../apps/desktop/src/main/agent/deepseek-agent-host.ts#L296) parses arguments before dispatch.
- Only the [MCP adapter:38](../../../apps/desktop/src/main/agent/agent-tools.ts#L38) extends the schema and strips the metadata before invocation.

**Observed behavior:** A synthetic response read the real outgoing session prompt, extracted its execution ID, and returned `aves_dashboard_canvases` with `{request:{type:'list'}, executionId}`. The real session manager and direct host made two provider-stub requests but dispatched zero tool invocations. The next request contained the generic invalid-tool-arguments result. This confirms the contract conflict; it does not claim every model response follows the instruction.

**Impact:** Valid tool intent is rejected by mutually inconsistent host instructions and schemas. A basic canvas-list operation can fail before reaching the service.

**Missing or inadequate verification:** The successful round-trip test [calls the host directly](../../../apps/desktop/test/integration/deepseek-agent.test.ts#L237). Session-aware cancellation cases use controlled argument payloads; they do not construct a tool call by following the outgoing session instruction.

**Minimum sufficient remediation:** Keep execution authorization out of model arguments for the direct host. Remove transport-specific argument guidance from the shared session prompt, or add it only in an adapter that actually owns that transport contract. Preserve the trusted execution ID and revocable callback; do not let the model choose authorization identity.

**Verification scope:** One session-to-direct-host-to-tool round trip that inspects the emitted prompt and schemas, plus the existing direct-agent cancellation/authorization tests. Compile and lint the affected desktop modules. Retain separate legacy gateway boundary tests if its adapter changes.

### AUDIT-002 - Block task status follows the conversation instead of the launched execution

**Class:** `defect`

**Severity:** P2

**Confidence:** High

**Area:** Ownership of session lifecycle versus block action lifecycle.

**Reachability:** Start an `agent.task` block action, then use recoverable `cancelTurn` on that session and wait for cancellation to settle.

**Blast radius:** Subsequent actions on that block generation, including actions unrelated to the cancelled Agent task.

**Reversibility:** No data loss was demonstrated. Another click or snapshot refresh does not clear the block. Ending/removing the associated session, a later successful turn, or clearing runtime state can change the projection; normal cancellation alone does not.

**Documented trade-off:** [Dashboard blocks:123](../../../docs/dashboard-blocks.md#L123) reflects terminal task status and permits only one active action per block. [Agent sessions:86](../../../docs/agent-sessions.md#L86) makes cancellation recoverable so the same conversation can be reused.

**Decision status:** `drift`

**Why this finding is outside the accepted boundary:** A reusable idle conversation is not evidence that its previous block action is still executing. The admission restriction remains valid, but it consumes the wrong lifecycle.

**Evidence:**

- [desktop-application.ts:378](../../../apps/desktop/src/main/desktop-application.ts#L378) returns a session ID as the task handle; [taskResult:389](../../../apps/desktop/src/main/desktop-application.ts#L389) projects `snapshot.status` and all message chunks from the session.
- [block-runtime-types.ts:36](../../../apps/desktop/src/main/canvas/blocks/block-runtime-types.ts#L36) exposes only a session-shaped task ID/status result, losing execution identity.
- [session-execution.ts:151](../../../apps/desktop/src/main/agent/sessions/session-execution.ts#L151) correctly maps a cancelled execution to an idle reusable session.
- [block-snapshots.ts:15](../../../apps/desktop/src/main/canvas/blocks/block-snapshots.ts#L15) maps idle to running, and [block-runtime.ts:427](../../../apps/desktop/src/main/canvas/blocks/block-runtime.ts#L427) refuses a new action while any projected record is running.

**Observed behavior:** A reproduction used real `AgentSessions`, an abort-aware `DeepSeekAgentHost` request stub, and real `BlockSnapshots` with the application adapter's projection. After cancellation settled: `sessionStatus='idle'`, `executionStatus='cancelled'`, and `blockActionStatus='running'`. That snapshot satisfies the actual Busy rejection predicate. The observation does not depend on cancellation timing after settlement.

**Impact:** The block remains busy after its work has ended. The same projection also reads the entire evolving conversation instead of an immutable result belonging to the original action.

**Missing or inadequate verification:** [Canvas block tests](../../../apps/desktop/test/integration/canvas-blocks.test.ts#L149) supply a synthetic task handle and no real task-result lifecycle. Session cancellation is tested separately, leaving this adapter uncovered.

**Minimum sufficient remediation:** Track the execution launched for the block and retain its terminal outcome. Preserve the distinction between not-yet-started work and a cancelled execution; simply mapping every idle session to an error would misclassify legitimate startup. A subsequent conversation turn must not reopen or rewrite an already settled action result.

**Verification scope:** Adapter tests for startup, completion, recoverable cancellation, and reuse of the same conversation; assert that a later block action can be admitted after cancellation. Retain block ownership and execution-cancellation tests. Use focused native verification when the resulting visible status behavior is changed.

### AUDIT-004 - Block document reads convert every failure into permission denied

**Class:** `defect`

**Severity:** P3

**Confidence:** High

**Area:** Safe error-code preservation between CanvasService and block runtime.

**Reachability:** A block mount, inspection, or other document read encounters unavailable storage or a missing canvas.

**Blast radius:** Callers using `DashboardBlockRuntime.document`; the direct canvas IPC path uses the existing correct mapper.

**Reversibility:** The original operation remains a read. Restoring storage or choosing an existing canvas can recover, but callers receive misleading failure semantics until then.

**Documented trade-off:** [AGENTS.md:70](../../../AGENTS.md#L70) requires preserving safe operational codes while sanitizing unknown failures. [Canvas service:43](../../../docs/canvas-service.md#L43) exposes structured safe failures.

**Decision status:** `drift`

**Why this finding is outside the accepted boundary:** CanvasService has already sanitized the failure. A second boundary discards that safe classification rather than protecting additional sensitive information.

**Evidence:**

- [block-runtime.ts:64](../../../apps/desktop/src/main/canvas/blocks/block-runtime.ts#L64) combines failed results and unexpected successful shapes in one `PermissionDenied` branch.
- [canvas-service.ts:115](../../../apps/desktop/src/main/canvas/canvas-service.ts#L115) preserves known service errors and maps unknown storage failures to `UNAVAILABLE`.
- [operation-failure.ts:14](../../../apps/desktop/src/main/operation-failure.ts#L14) already maps `UNAVAILABLE` to `SERVICE_NOT_READY` and `NOT_FOUND` to `NOT_FOUND`; [canvas-ipc.ts:42](../../../apps/desktop/src/main/ipc/canvas-ipc.ts#L42) uses that mapping.

**Observed behavior:** With real CanvasService and block runtime, a synthetic read failure returned domain `UNAVAILABLE` but boundary `PERMISSION_DENIED`. An absent canvas returned domain `NOT_FOUND` but again boundary `PERMISSION_DENIED`. Only Electron protocol registration was stubbed; no real file was read.

**Impact:** Users and callers cannot distinguish a missing resource or retryable storage failure from an authorization denial. Existing safe messages and recovery information are lost.

**Missing or inadequate verification:** The IPC error tests cover the shared mapper, but not this extra remapping inside block document reads.

**Minimum sufficient remediation:** Forward unsuccessful results through `canvasFailure`. Handle an unexpected successful result shape separately as an internal invariant failure. Keep the service's existing resource-concealment/authorization behavior intact.

**Verification scope:** Targeted document-read tests for unavailable, missing, and unauthorized cases plus existing IPC error serialization tests; affected desktop compile/lint.

### AUDIT-005 - Question-answer validation is reported as an internal operation failure

**Class:** `defect`

**Severity:** P3

**Confidence:** High

**Area:** Domain validation error taxonomy at the block-action boundary.

**Reachability:** A registered `agent.respond` action submits valid JSON with a missing required answer, unknown field, invalid text value, or invalid choice. Generated form validation does not replace host validation.

**Blast radius:** Feedback for invalid canvas question submissions. Invalid answers are still rejected before persistence.

**Reversibility:** Correcting the answer can succeed, but the current response does not identify a validation problem.

**Documented trade-off:** [Dashboard blocks:163](../../../docs/dashboard-blocks.md#L163) defines host-owned question fields and answers. [AGENTS.md:70](../../../AGENTS.md#L70) distinguishes safe operational failures from unknown exceptions.

**Decision status:** `drift`

**Why this finding is outside the accepted boundary:** Expected input rejection is known domain behavior. It should not become the generic category reserved for unexpected failures.

**Evidence:**

- [questionAnswers:131](../../../packages/workspace-model/src/canvas/dashboard-blocks.ts#L131) uses Zod for JSON structure but plain `Error` for the semantic validation branches at lines 141, 148, 154, and 167.
- [block-actions.ts:90](../../../apps/desktop/src/main/canvas/blocks/block-actions.ts#L90) calls that function without translating its known domain failures.
- [block-runtime.ts:434](../../../apps/desktop/src/main/canvas/blocks/block-runtime.ts#L434) serializes the failure through [operationFailure](../../../apps/desktop/src/main/operation-failure.ts#L31), where plain errors become `INTERNAL`.
- [canvas-ipc.ts:62](../../../apps/desktop/src/main/ipc/canvas-ipc.ts#L62) forwards that code/message to the renderer.

**Observed behavior:** Calling the real action executor for a question with one required text field and `answers:{}` produced `{code:'INTERNAL', message:'The operation failed. Please try again.'}` through the actual failure mapper. No write was needed to reproduce it.

**Impact:** A correctable form error looks like a system failure. Repeating the same input cannot fix it, and generated UI loses the safe reason that was already known by the validator.

**Missing or inadequate verification:** The inspected action/session suites do not assert error classification for question-answer semantic rejection.

**Minimum sufficient remediation:** Represent these failures as structured domain validation results/errors and translate them to `INVALID_ARGUMENT` at the host boundary, or express the semantics with the existing schema validation mechanism. Keep Electron/IPC dependencies out of the domain package and continue sanitizing genuinely unknown exceptions.

**Verification scope:** Cover the four semantic rejection categories and a valid answer, then assert the block/IPC boundary returns a safe invalid-argument failure without leaking supplied answer content.

### AUDIT-006 - Cancelled tools remain in progress in the transcript

**Class:** `defect`

**Severity:** P3

**Confidence:** High

**Area:** Transcript projection and terminal execution state.

**Reachability:** Cancel a turn while a tool invocation is awaiting completion, then allow the invocation/cancellation to settle normally.

**Blast radius:** Tool status displayed in that conversation's transcript; this observation does not establish an authorization or rollback failure.

**Reversibility:** The misleading row survives transcript reconstruction and remains until the relevant transcript/reset state is removed.

**Documented trade-off:** [Runtime architecture:149](../../../docs/runtime-architecture.md#L149) requires unfinished tool calls to become interrupted at turn end or connection failure. [Agent sessions:90](../../../docs/agent-sessions.md#L90) explicitly does not promise rollback of admitted operations.

**Decision status:** `drift`

**Why this finding is outside the accepted boundary:** The renderer should reflect that execution ended without pretending an admitted operation was undone. Leaving a terminal turn's tool visually running satisfies neither requirement.

**Evidence:**

- [deepseek-agent-host.ts:284](../../../apps/desktop/src/main/agent/deepseek-agent-host.ts#L284) emits `in_progress`; [line 327](../../../apps/desktop/src/main/agent/deepseek-agent-host.ts#L327) checks revocation before emitting its completed/failed update.
- [ChatTranscript.tsx:23](../../../packages-renderer/controller/src/chat/ChatTranscript.tsx#L23) reduces events without considering terminal execution state.
- [agent-transcript.ts:26](../../../packages-renderer/controller/src/chat/agent-transcript.ts#L26) ignores terminal/status events. The [existing finishTools helper:85](../../../packages-renderer/controller/src/chat/agent-transcript.ts#L85) marks unfinished calls interrupted, but has no caller.

**Observed behavior:** A real host emitted a tool start, awaited a controlled tool, and was cancelled before that tool was released. Reducing its emitted events with the current transcript code left `status='in_progress'`. Applying the unused finalizer produced `interrupted`.

**Impact:** The timeline contradicts settled task state and suggests work is still active after cancellation.

**Missing or inadequate verification:** Cancellation tests verify execution revocation and context recovery, but do not project the resulting events into the conversation transcript.

**Minimum sufficient remediation:** Finalize unfinished tool rows at the correct execution/turn boundary, including cancellation and failure. Reuse or integrate the existing finalizer with explicit turn ownership; do not mark tools from a newer active turn interrupted while processing older state.

**Verification scope:** Transcript behavior tests using actual cancellation/error event sequences and a subsequent turn, plus focused visual verification of the terminal label when implementing the change.

### AUDIT-008 - Block-local HTML selection resolves to the body node

**Class:** `defect`

**Severity:** P3

**Confidence:** High

**Area:** Generated-document DOM compatibility adapter.

**Reachability:** Generated block JavaScript calls `document.querySelector('html')` to read or update its local HTML element.

**Blast radius:** That block's presentation logic. No cross-block access or privileged escape was demonstrated.

**Reversibility:** Using `document.documentElement` avoids the mismatch; fixing the adapter restores selector consistency without changing the isolation model.

**Documented trade-off:** [Dashboard blocks:81](../../../docs/dashboard-blocks.md#L81) documents block-local DOM queries and distinct local body/HTML nodes. Shadow DOM is an accepted presentation/lifecycle boundary, not a per-block security boundary.

**Decision status:** `drift`

**Why this finding is outside the accepted boundary:** Local scoping does not require changing the meaning of the `html` selector to `body`.

**Evidence:**

- [canvas-document.ts:102](../../../apps/desktop/src/main/canvas/canvas-document.ts#L102) creates separate local HTML and body elements.
- [canvas-document.ts:109](../../../apps/desktop/src/main/canvas/canvas-document.ts#L109) correctly exposes HTML as `documentElement`, but [line 111](../../../apps/desktop/src/main/canvas/canvas-document.ts#L111) returns the body for both selectors. `querySelectorAll` delegates to the local root instead.

**Observed behavior:** An isolated reproduction executed the actual proxy fragment against a synthetic Shadow DOM. `querySelector('html').tagName` was `BODY`, while `querySelectorAll('html')[0].tagName` and `documentElement.tagName` were both `HTML`. This checked the adapter directly, not an Electron screenshot or complete sandbox lifecycle.

**Impact:** Code setting HTML-level classes, attributes, or inherited presentation state updates a different node than equivalent DOM APIs.

**Missing or inadequate verification:** Current block tests do not assert these local-document selector identities.

**Minimum sufficient remediation:** Resolve `html` to the local HTML node, or consistently delegate both selectors to the scoped root. Do not broaden access to the real outer document.

**Verification scope:** Check local body/HTML selector identities and regular scoped selectors; exercise one real sandbox block using an HTML-level class when implementing the rendered change.

## Hardening Opportunities

These are code-quality observations, not additional confirmed product failures. Style-only drift remains in this section. Each opportunity has a bounded revisit condition; none is required merely to increase abstraction or reduce file length.

### HARDENING-001 - Maintain sandbox runtime code as checkable source

**Class / decision status:** `hardening` / `drift` from maintained-source readability rules.

**Current posture:** The canvas's opaque-origin document and CSP are intentional. However, [canvas-document.ts:11](../../../apps/desktop/src/main/canvas/canvas-document.ts#L11) embeds roughly 200 lines of handwritten runtime code in `String.raw`, with compact multi-statement lines and untyped messages. The retained [local-widget loader:87](../../../apps/desktop/src/main/plugins/local-widget-sandbox.ts#L87) also embeds executable JavaScript in HTML strings. The enclosing files pass lint without checking those programs. This differs from [AGENTS.md:64](../../../AGENTS.md#L64); AUDIT-008 is one concrete defect inside that blind spot.

**Incremental benefit:** Keeping maintained runtime logic in a dedicated browser-source entry allows normal formatting, type checking, imports, and focused tests; a build step can still inline the resulting script into the same sandbox document.

**Cost and coupling:** Requires a small build/asset handoff and care around escaping, CSP, and script execution. Keep the code outside the privileged renderer and preserve current isolation. Do not introduce a new sandbox framework.

**Revisit when:** Next changing the canvas bridge, DOM shim, or lifecycle tracking. The one-line selector repair does not require this extraction first.

### HARDENING-002 - Give block-to-Agent orchestration an explicit owner
